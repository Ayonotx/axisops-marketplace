# AxisOps Android Packaging & Deployment Recipe

**The signed APK and AAB already exist** in `android/` — built and verified on this machine. What remains: deploy the site to a public HTTPS URL (needs an account — yours), rebuild the TWA with the real domain, and create the Play Console account. Everything is below.

It opens the app in fullscreen TWA (localhost build = only works while your PC's dev server runs — that's expected; the real build comes after deployment).

## 2. Deploy to public HTTPS (your step — needs an account)

Our stack is **Next.js (Node) + SQLite file DB**, so it needs a Node server with a persistent disk — *not* serverless (Vercel kills SQLite). Cheapest good fits:

### Option A — Railway (easiest, ~$5/mo)
1. Push the project to a GitHub repo (private is fine). ⚠️ **Before pushing:** make sure `.env.local`, `android/KEYSTORE-SECRET.txt`, `data/axisops.db` are git-ignored — they hold secrets and the live DB.
2. railway.com → New Project → Deploy from GitHub repo.
3. Add a **Volume** mounted at `/app/data` (Railway: Service → Volumes → mount path `/app/data`) so `data/axisops.db` survives restarts.
4. Set environment variables in Railway (copy values from your local `.env.local`): `PAYSTACK_SECRET_KEY`, `PAYSTACK_PUBLIC_KEY`, `ARKEL_API_KEY`, `ARKEL_SENDER_ID`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `TWA_PACKAGE_NAME`, `TWA_CERT_SHA256`.
5. Build command: `npm install && npm run build` · Start command: `npm start` (Railway auto-detects Next.js if you leave them blank).
6. Settings → Networking → Generate Domain → you get `https://something.up.railway.app`. Set that as your **app URL** (custom domains work too — add your own domain if you have one, e.g. `app.axisops.com`).
7. Verify: open the URL → sign in with OTP → check `https://<your-url>/.well-known/assetlinks.json` returns the statement JSON.

### Option B — cheap VPS (Hetzner CX22 ≈ €4/mo)
1. Create Ubuntu 24.04 VPS, add your SSH key.
2. `apt update && apt install -y nodejs npm nginx` (Node 22+), `npm i -g pm2`.
3. Copy the project (git clone or scp; again: no `.env.local` secrets in the repo — create `.env.local` on the server).
4. `npm install && npm run build && pm2 start npm --name axisops -- start`.
5. Nginx reverse proxy `server_name your.domain.com` → `proxy_pass http://localhost:3000` + `certbot --nginx` for free HTTPS.
6. Point your domain's DNS A record at the VPS IP.

**Wherever you deploy:** the app auto-creates/migrates the SQLite DB on first run (`data/axisops.db`). Back that file up periodically — it is the whole business (users, deals, wallets, ledger).

## 3. Rebuild the TWA with your real domain (5 minutes)

1. Edit `android/twa-manifest.json`: replace `localhost:62664` with your deployed host (e.g. `something.up.railway.app`) in **`host`**, **`iconUrl`** and **`maskableIconUrl`** (icon URLs must be the public HTTPS URLs).
2. From the project root:
   ```bash
   cd android
   # Windows: use the two-command variant below (see §5 for why)
   npx bubblewrap update --manifest twa-manifest.json
   npx bubblewrap build --skipPwaValidation
   ```
   **On this Windows machine, run instead** (handles the two toolchain bugs documented in §5):
   ```bash
   cd android
   PW=$(grep "Store password" KEYSTORE-SECRET.txt | awk '{print $3}')
   env -u NoDefaultCurrentDirectoryInExePath BUBBLEWRAP_KEYSTORE_PASSWORD="$PW" BUBBLEWRAP_KEY_PASSWORD="$PW" npx bubblewrap update --manifest twa-manifest.json   # answer the versionName prompt
   env -u NoDefaultCurrentDirectoryInExePath BUBBLEWRAP_KEYSTORE_PASSWORD="$PW" BUBBLEWRAP_KEY_PASSWORD="$PW" npx bubblewrap build --skipPwaValidation
   # bubblewrap's last apksigner step has a Windows path bug — finish signing:
   cmd //c "scripts\\sign-apk.bat"    (from project root)
   ```
3. Update the version before each Play release: bump `appVersionCode` (integer, +1 every release) and `appVersionName` in `android/twa-manifest.json`, then rebuild.
4. Test on your phone: install the new signed APK, confirm it opens your live site fullscreen, no browser bar, notifications work.

## 4. Publish to Play Store (your step — needs a $25 account)

1. Create a Google Play **Console** developer account (one-time $25, needs ID verification, can take days for the first review).
2. Play Console → Create app → name "AxisOps Marketplace" → default language → App → Free.
3. **App signing:** Play will ask about signing keys — accept *Play App Signing* (Google manages the app key; your `axisops-upload.jks` stays the **upload key** you sign every release with).
4. **Domain verification / App content:** Play asks to verify your website for the TWA. It checks `https://<your-domain>/.well-known/assetlinks.json` — already implemented; just make sure the deployed site responds with the JSON (§2 step 7). Also verify via https://developers.google.com/digital-asset-links/tools/generator
5. Store listing: description, screenshots (phone screenshots of your real app), the 512px icon (`public/icons/icon-512.png`), feature graphic 1024×500.
6. **Data safety form:** you collect phone numbers (OTP), messages, payment data via Paystack — answer accordingly. Escrow = "financial features" declaration.
7. Upload `android/app-release.aab` to Production (or start with Internal testing track — recommended for the first release) → submit for review.

## 5. Windows toolchain bugs hit during the build (already solved on this machine)

Recorded so a rebuild never re-hunts them:

1. **bubblewrap needs `Sdk/bin` + `Sdk/lib` at the SDK root** (legacy layout check). Fixed with directory junctions:
   `mklink /J "%LOCALAPPDATA%\Android\Sdk\bin" "%LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest\bin"` and the same for `lib`.
2. **`NoDefaultCurrentDirectoryInExePath=1`** is set in this environment → cmd refuses to run `gradlew.bat` from the project dir → build dies with "'gradlew.bat' is not recognized". Fix: `env -u NoDefaultCurrentDirectoryInExePath npx bubblewrap build …`.
3. **bubblewrap doesn't quote JAVA_HOME** when invoking apksigner → `"C:\Program Files\..."` splits at the space → signing crashes. Fix: sign manually with the space-free JDK — `cmd //c "scripts\sign-apk.bat"` (uses `%LOCALAPPDATA%\Android\jdk17\...`).
4. **Password prompts** are skipped with `BUBBLEWRAP_KEYSTORE_PASSWORD` + `BUBBLEWRAP_KEY_PASSWORD` env vars (otherwise interactive-only).
5. `~/.bubblewrap/config.json` pins the JDK (`C:/Program Files/Eclipse Adoptium/jdk-17.0.20.101-hotspot`) and SDK (`C:/Users/Admin/AppData/Local/Android/Sdk`) so bubblewrap never downloads its own toolchain.
